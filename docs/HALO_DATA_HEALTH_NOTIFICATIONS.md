# HALO Data Health notifications

HALO owns the alert decision and delivery. EventBridge invokes the existing Noise Lambda at `POST /api/halo-data-health` every five minutes; that route only POSTs `{}` to HALO's `POST /api/data-health/notify`. The relay never reads Noise health or sends WhatsApp messages.

Apply `supabase/halo_data_health_notifications.sql` in the shared Supabase project before enabling the scheduler. The `ops` schema must be exposed to PostgREST. HALO needs these server-only Amplify variables: `HALO_DATA_HEALTH_TOKEN` (at least 32 random characters), `HALO_DATA_HEALTH_SEND_URL` (the listener `/send-message` HTTPS URL), `HALO_DATA_HEALTH_GROUP_ID` (one internal team group), `HALO_DATA_HEALTH_CLIENT_ID`, `HALO_DATA_HEALTH_INSTANCE_NAME`, and `HALO_DATA_HEALTH_LISTENER_TOKEN` (the listener proxy token, without `Bearer `). Noise Lambda needs `HALO_DATA_HEALTH_URL=https://<halo-host>/api/data-health/notify` and the same `HALO_DATA_HEALTH_TOKEN`.

The route reports current red and amber readings, current standing faults and whole-service findings, and the newest process failure only if it ran within fifteen minutes. Stale readings are eligible at 08:00, 12:00, 16:00, and 20:00 SGT. Sends are restricted to 08:00–21:59 SGT. Each message has a coloured circle, project, service, signal, and bullet-pointed evidence. It does not send recovery notices.

`ops.data_health_notifications` is a durable unique-key claim before delivery. The same finding is sent at most once per Singapore day; stale readings once per four-hour slot. An ambiguous listener result remains `unconfirmed` and is not retried blindly, because the listener may already have queued it. Inspect the ledger and listener queue when a relay run fails. At most four new messages are sent per invocation to fit Amplify's request limit; later ticks continue the backlog. Removing the EventBridge rule immediately stops new evaluations. Existing service-owned Noise and WBGT Data Health crons remain separate until the HALO path has been verified live and deliberately cut over.
